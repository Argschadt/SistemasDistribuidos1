3. O que mudou e por que agora faz todo sentido?

  • Mudança 1 — Erros caíram de 7%–14% para 0,00% (Zero Erros!): Com a colocação do NGINX na porta 5000 distribuindo a carga para 2 réplicas do Flask (portas 5001 e 5002), nenhuma das 10.800 requisições falhou. O NGINX gerenciou a fila de entrada de conexões HTTP sem deixar o Flask rejeitar clientes.
  • Mudança 2 — O Índice B-Tree agora melhorou drasticamente o desempenho (até 40% mais rápido): Ao corrigirmos a consulta SQL na API para realmente filtrar por WHERE cidade = 'Manaus', o banco 100k COM Índice usou Index Scan e reduziu o tempo médio de 2.687 ms para 1.607 ms no cenário de leitura intensa (75/25), aumentando a vazão de 86,84 req/s para 103,45 req/s.
  • Mudança 3 — Reduzir de 100k para 20k (ambos sem índice) reduziu a latência quase pela metade: Como sem índice o PostgreSQL precisa ler a tabela inteira (Sequential Scan), ler apenas 20.000 registros baixou o tempo médio de 2.304 ms para 1.191 ms no cenário 50/50 (e de 2.687 ms para 1.675 ms no 75/25).
